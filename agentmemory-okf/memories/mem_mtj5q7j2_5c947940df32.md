Explain how the persistence controller works with the shared model container.

---

### 🤖 Assistant

The persistence controller is responsible for managing the Core Data stack, which includes the persistent container. The shared model container is a singleton instance that provides access to the managed object context and coordinates data saving and fetching operations across the app.

Here's a high-level overview of how it works:

1. **Initialization**: The shared model container is typically initialized once, often in the app delegate or a central place in your app's lifecycle. This initialization sets up the Core Data stack, including the persistent store coordinator, managed object model, and managed object context.

2. **Persistent Container**: The persistent container is a property of the persistence controller. It loads the Core Data model and sets up the persistent store (like an SQLite database) where your data will be stored.

3. **Managed Object Context**: The managed object context is a workspace where you create, read, update, and delete managed objects. It tracks changes and can be used to fetch data from the persistent store.

4. **Saving Changes**: When you make changes to the managed objects in the context, you save these changes to persist them. The persistent controller handles saving these changes to the persistent store, ensuring data consistency.

5. **Shared Instance**: By having a shared instance of the persistence controller, you ensure that all parts of your app access the same Core Data stack, which helps maintain a consistent state and avoid data conflicts.
