# Python Process Examination (macOS)

## When to Use
- "What are the top memory-hog processes?" / "What's using all the RAM?"
- "Look into the python processes." / "What's all this python?"
- Auditing local inference servers (TurboQuant-MLX), the Hermes gateway/service
  sprawl, or stray uvicorn/dev servers on a Mac dev box.
- Anytime a naive `ps -r` or `ps -o comm` gave a misleading answer.

Use when the user asks which processes are hogging memory, what the python
processes are, or to audit local inference servers (TurboQuant-MLX), Hermes
gateway/service sprawl, or stray uvicorn/dev servers on a Mac dev box.

## Why the naive `ps` lies (gotchas)
1. **`-r` sorts by CPU, not memory.** `ps -A -o pid,rss,comm -r` returns the
   busiest-by-CPU processes (rg, tiny daemons). It does NOT answer "top memory".
   Do not use it for a memory question.
2. **`-comm` truncates to the basename.** `ps ... -o comm` shows `python` /
   `python3.13` and hides *what* is actually running. The 1.8 GB TurboQuant
   model server shows up as just `python` and is invisible without the full
   args. **Always use `args` (full command line), not `comm`.**
3. **RSS from `ps` is in KB.** Divide by 1024 for MB.
4. **Hermes fanout is real but individually tiny.** The agent spawns many
   `mcp_stdio_watchdog` children (~1.2 MB each) under multiple gateway/session
   parent PIDs. Individually negligible; aggregated they add up (e.g. 168 procs
   ≈ 233 MB). Report the aggregate, not each PID.

## Recipe: top python processes by RSS (full args)
```bash
ps -A -o pid,rss,args | awk 'NR>1{
  pid=$1; rss=$2; $1=""; $2=""; line=substr($0,3);
  if (line ~ /python/) printf "%.1f\t%s\t%s\n", rss/1024, pid, line
}' | sort -rn | head -15
```
Pitfall: do NOT additionally pre-filter the pipe before the awk just to match
python — the awk already filters, and piping through `sort`/`head` separately is
fine, but keep the `args` field so you can see the real process. (Prefer
search_files / read_file for content and file lookups; this recipe is a live
`ps` snapshot, not a file search.)

## Recipe: classify & total (Python one-shot)
Run as a Python script so you can categorize by signature and sum per class:
```python
from subprocess import run
out = run(["ps","-A","-o","pid,rss,args"], capture_output=True, text=True).stdout.splitlines()
rows=[]
for ln in out:
    p=ln.split(None,2)
    if len(p)<3: continue
    try: pid=int(p[0]); rss=int(p[1])
    except ValueError: continue
    if "python" not in p[2].lower(): continue
    rows.append((pid,rss,p[2]))
total=sum(r for _,r,_ in rows)
# classify by signature substring:
#   "turboquant_mlx.serve" -> TurboQuant-MLX model server (the big one)
#   "tui_gateway.entry"    -> agent runtime
#   "slash_worker"         -> slash command worker
#   "hermes serve"         -> hermes desktop serve / hermes_cli serve
#   "mcp_stdio_watchdog"   -> MCP server watchdogs (aggregate these)
#   "uvicorn app.main"     -> dev server on :5001
```
Sum RSS per class; lead the report with the top class by bytes.
