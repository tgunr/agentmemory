### 🤖 Assistant

That error means your bundled app can’t find `ui.py` at runtime. Most likely you built from `mac/` but `ui.py` lives one directory up (`/Volumes/Work/unsub-mail`). PyInstaller only searches its own working paths unless you tell it otherwise.

Here are 3 quick fixes—pick one:

#1 (fastest): add parent dir to PyInstaller paths  
Run your build with an extra search path for the source root:
```bash
# from /Volumes/Work/unsub-mail/mac
.venv/bin/pyinstaller -y --windowed --name UnsubMail \
  --icon assets/app.icns \
  --paths .. \
  --hidden-import ui \
  ../main.py
```
`--paths ..` makes the parent folder importable so `import ui` works.

#2 (spec file, preferred/consistent)
If you’re already using a `.spec`, add the project root to `pathex` and (optionally) list `ui` as a hidden import:
```python
# UnsubMail.spec
a = Analysis(
    ['../main.py'],
    pathex=['/Volumes/Work/unsub-mail'],   # <-- add this
    hiddenimports=['ui'],                  # <-- belt & suspenders
    ...
)
```
Then rebuild:
```bash
.venv/bin/pyinstaller -y UnsubMail.spec
```

#3 (project layout / import hygiene)
Make the app a package so relative imports are stable:
```
unsub-mail/
  app/
    __init__.py
    main.py
    ui.py
mac/
  Makefile
```
In `main.py` use:
```python
from . import ui
```
Then build with:
```bash
.venv/bin/pyinstaller -y --windowed --name UnsubMail \
  --icon assets/app.icns \
  --paths ../app \
  app/main.py
```

Sanity checks:
- Ensure the module name is exactly `ui.py` (case-sensitive).
- Don’t have another file named `ui` (dir) shadowing it.
- If you moved files, clean before rebuilding:
  ```bash
  rm -rf build dist UnsubMail.spec
  ```
