### 👤 User

Is there any other way to connect to a Snapmaker 2 A350 other than using Luban wirelessly?

---

### 🤖 Assistant

Yeah—Luban wireless isn’t your only option. You’ve got a few solid alternatives depending on what you’re trying to do:

### 1. USB (most direct + reliable)
- Connect your computer to the A350 via USB.
- Luban can still be used, just over USB instead of Wi-Fi.
- You can also use other G-code senders (like Pronterface, though Snapmaker isn’t officially supported everywhere).

### 2. USB Drive (offline workflow)
- Export your G-code file.
- Put it on a USB flash drive.
- Plug it into the Snapmaker and run it directly from the touchscreen.

### 3. Ethernet (if you add it)
- The A350 itself doesn’t natively support Ethernet, but some users use network bridges or Wi-Fi-to-Ethernet adapters to get a more stable “wired” network connection.
- Still ends up behaving like a network connection (used via Luban or API).

### 4. Serial / Terminal control
- You can connect over USB and talk directly using a serial terminal (like `screen`, `minicom`, or Pronterface).
- This gives you raw control via G-code commands.

### 5.

Third-party integrations (limited)
- Not as open as something like Marlin/OctoPrint setups, but:
  - Some people hack together OctoPrint setups via USB.
  - API access is unofficial but exists (reverse-engineered).

### 6. Touchscreen (fully standalone)
- You don’t need a computer at all after setup.
- Load files via USB and control everything from the machine.

---

### Quick takeaway
If you want to avoid Luban wireless specifically:
- Best alternative: **USB cable**
- Most convenient offline: **USB drive**
- Most “advanced tinkering”: **OctoPrint via USB**

If you tell me your goal (remote control, automation, stability, etc.), I can suggest the cleanest setup 👍

### 👤 User

My Snapmaker is several feet away, and I would prefer to connect to it wirelessly but not using Luban.

---

### 🤖 Assistant

Got it — you want **wireless control, but without Luban**. That’s doable, but Snapmaker doesn’t officially make it easy, so you’re looking at workarounds.

Here are your real options:

### ✅ Best practical option: OctoPrint (wireless via USB bridge)
- Plug a **Raspberry Pi (or similar mini PC)** into the Snapmaker via USB
- Run **OctoPrint** on the Pi
- Access it wirelessly from your browser

**Why this works well:**
- Fully wireless from your computer
- Much better UI/control than Luban
- Supports file upload, monitoring, plugins, etc.

**Caveat:**
- Snapmaker isn’t “officially supported,” but it works using a **Marlin-compatible profile**
- You may need a bit of config tweaking

---

### ✅ Alternative: Wi-Fi serial bridge (advanced / DIY)
- Use something like an **ESP32 or Wi-Fi serial adapter**
- Bridge Snapmaker’s USB serial to Wi-Fi

**Result:**
- You connect over network sockets instead of Luban

**Reality check:**
- More hacky
- Less stable than OctoPrint
- No nice UI unless you build one

---

### ✅

Semi-hidden option: Snapmaker network API
- The A350 exposes a **network interface over Wi-Fi**
- Luban uses it, but it’s not well documented

Some people:
- Reverse-engineer the protocol
- Send G-code over TCP

**Downside:**
- Not officially supported
- Can break with firmware updates
- Requires scripting

---

### 🚫 What you *can’t* really do
- Connect directly via standard Wi-Fi like a normal printer (no native open protocol)
- Use common wireless slicers (PrusaSlicer, Cura) directly over network without middleware

---

### 👍 Recommendation
If you want something that just works and feels clean:

→ **Go with OctoPrint + Raspberry Pi**

It basically gives you:
- Wireless uploads
- Remote control
- Webcam support
- No Luban dependency
