# Summary

The project store fetches fully hydrated repository, lane, and session groupings when a user enters a project, preserving backend tree membership and IDs. Repository scanning is desktop-only and guarded to avoid repeated disk walks during one app run unless explicitly forced.

## Facts
- `fetchProjectSessions(projectId)` calls `projects.project_sessions` with `project_id` and returns the hydrated `SidebarProjectTree` or null on missing data or failure.
- `scanAndRecordRepos(force)` uses `desktopGit()?.scanRepos`, skips unavailable scans and repeated scans unless forced, then marks `didScanRepos` and `$reposScanning`.
- Repository discovery is designed as one heavy filesystem scan per app run, with backend caching and session-derived fallback outside desktop.
