# Summary

The inspected handlers ensure profile changes fully reset the active draft against the selected gateway backend and handle theme changes without unnecessarily creating sessions. Title operations intentionally follow the gateway RPC path for reliability, while bare title queries remain delegated to command execution.

## Facts
- Profile switching normalizes the matched profile name, updates $newChatProfile, awaits ensureGatewayProfile, then calls startFreshSessionDraft so the sidebar and composer rebuild against the new backend profile.
- A successful profile change displays copy.newChatsProfile(match.name); failures are passed to notifyError with copy.setProfileFailed.
- The skin handler uses sessionHint or activeSessionIdRef.current, applies handleSkinCommand(arg), and displays a success toast when no session exists rather than creating a backend session.
- When a session exists, the skin handler appends a system message, optionally formatted with slashStatusText when recordInput is enabled.
- The title handler delegates bare /title to runExec; comments state named titles use the gateway session.title RPC because REST renameSession returns 404 for runtime IDs and slash-worker database writes may silently fail.
