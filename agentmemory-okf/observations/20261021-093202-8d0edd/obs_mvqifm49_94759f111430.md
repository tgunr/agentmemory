# Summary

There is no event to attach to, so hook-based integration fails.
  Viable integration paths:
  1. MCP server — Kilo can load an MCP server (stdio) via
     `mcp_settings.json`. This lets a Kilo *agent* call external tools
     when it chooses, but it is NOT automatic per-message capture.
  2. File watcher on the tasks JSON dir — a `launchd`/`fswatch` daemon watches
     `.../globalStorage/kilocode.kilo-code/tasks/*/`; on write, parse new messages
     and push (e.g. `remember`) into the external system, tagged `source:kilo`,
     `task:<uuid>`, deduped by content hash. Automatic, survives reboots.
  3. Scheduled batch indexer — run a consolidation/index job on cron
     (e.g. OKF→AM indexer) for periodic full capture.
  4. Manual MCP side-channel — an agent-triggered "sync current task" action.
