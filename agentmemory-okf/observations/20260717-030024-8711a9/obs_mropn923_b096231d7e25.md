# Summary

The hermes-service-debugging skill was loaded to guide diagnosis of services that expose empty data, use incorrect ports, or silently fail API requests. It emphasizes verifying API versus viewer ports, effective launchd configuration, storage backend and canonical data paths before treating missing sessions as data loss.

## Facts
- Hermes commonly splits the REST API onto port 3111 and the viewer UI onto port 3113.
- iii-engine StateModule storage depends on store_method in iii-config.yaml: Redis uses state:mem:* keys, while file storage uses URL-encoded per-scope JSON .bin files under state_store.db/.
- The canonical state directory is usually AGENTMEMORY_DATA_DIR rather than the repository data/state_store.db/ directory, which is empty at build time.
- Launchd environment handling differs from manual service starts and can cause port, authentication, data-path, and restart-loop failures.
- Known traps include adapter-schema silent fallback, native-module ABI mismatch, embedding dimension mismatch, chat-only embedding gateways, swallowed viewer API errors, and separate Hermes versus agentmemory session stores.
